The three methods

METHOD 1Claude skillinterview + improv

Claude does the interview

A PM opens a Claude (Cowork) chat and talks to the tool. Claude runs the workplan-estimate skill: it interviews the PM, pulls comparable projects, runs the real Python scoring scripts, and narrates the draft — adjusting live as the PM pushes back ("drop that comparable", "add a discipline").

What it's best at
  • Messy, free-form input — no forms
  • Judgment calls & live iteration
  • Audience-driven "improv" demos
  • Explaining why, in plain language
Trade-offs
  • Needs Claude/Cowork seats + skill set up
  • Conversation varies (numbers don't)
  • Consistency across users is looser
Is it a skill? Yes — Method 1 is a Claude skill (workplan-estimate): the structured Q&A workflow plus the Python scripts, living in the connected workplanningtool folder.

How to demo it: open a Cowork chat with that folder connected, then say Run the workplan demo (or "Run improv" to let the room drive). Claude walks the PM exchange from DEMO_RUNBOOK.md and shows genuinely computed results in the chat. Nothing is faked — the same scripts power all three methods.
METHOD 2Guided web appAI / API-connectable

The self-serve web app

Method 1's interview, as a web page any PM can use with zero training. Paste the client scope and let the AI layer pre-fill it, or answer one question at a time. Then a full, editable breakdown — hours by phase, discipline and role, with a live-adjustable fee and a RAIC cross-check.

What it's best at
  • Firm-wide use without Claude seats
  • Consistent, guided intake
  • Editable per-discipline workplans
  • The AI layer is optional & swappable
Trade-offs
  • Most to build & host for real
  • Someone owns the deployment
How to demo it: open the tool and paste a client brief into the AI box, or click through the five questions. Try the per-discipline tabs — every hours cell is editable and the fee re-totals live. Open Method 2 — Guided web app ›
METHOD 3Standalone HTMLno AI · offline

The deterministic engine, in one file

A single HTML file with the engine and data wired in — no AI, no server, no network. It shows everything: every candidate's component scores, the full breakdown, and the actual Python source embedded. It "learns" by accumulating evidence: curate projects in Claude, export JSON, drop them in.

What it's best at
  • Total transparency & auditability
  • Finance/QA trust — every number traces
  • No AI cost, no API, works offline
  • The core the other two sit on
Trade-offs
  • No natural-language input (menus only)
  • Manual data curation
How to demo it: open the file, set the parameters, press Compute. Expand the "reference engine" panels to show the real Python is embedded. Drop in a JSON file to grow the knowledge base live. Open Method 3 — Standalone engine ›

The shared engine

Same math under all three

Case-based reasoning, not ML. Comparables are scored on typology (40%), log-scaled GFA closeness (25%), modifier overlap (25%) and recency (10%); anything above a 0.35 similarity bar is blended by weight and scaled to size. Real firm reference data — 7 phases, discipline splits, 14 modifiers, the rate schedule — turns hours into a costed, multidisciplinary workplan. A draft starting point for the PM's judgment, never a final fee.

PM input→Comparables scoring (Python)→Phase × discipline × role blend→Modifiers + rates→Draft workplan
Demonstration build. Fees use an indicative AB rate schedule and a placeholder RAIC band; comparable projects are synthetic pending curation of the real Airtable set. The Python scoring and resourcing scripts are the source of truth — the web tools are a verified line-for-line JavaScript port producing identical numbers.
